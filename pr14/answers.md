# Ответы на вопросы — ПР14 (Работа с Fetch API)

## 1. В чем разница между Fetch API и XMLHttpRequest?
`Fetch` — современный стандарт, основанный на промисах (`Promise`), с более чистым и гибким синтаксисом. `XMLHttpRequest` (XHR) — устаревший API на основе событий (callback-style). Fetch проще читать и комбинировать с `async/await`, но XHR имеет встроенную поддержку отслеживания прогресса загрузки файлов.

## 2. Как обрабатываются ошибки в Fetch API и почему HTTP статус 404 не вызывает reject?
`Fetch` возвращает `reject` только в случае **сетевых ошибок** (например, нет интернета или неверный домен). Если сервер ответил (даже ошибкой 404 или 500), промис переходит в состояние `resolve`. Поэтому разработчик должен сам проверять свойство `response.ok` (оно равно `true` для статусов 200-299) и вручную выбрасывать ошибку (`throw new Error()`).

## 3. Какие методы HTTP поддерживает Fetch API?
Поддерживаются все методы: `GET` (получение), `POST` (создание), `PUT` (полное обновление), `PATCH` (частичное обновление), `DELETE` (удаление), а также `HEAD`, `OPTIONS`. Метод указывается в объекте настроек запроса: `fetch(url, { method: 'POST' })`.

## 4. Как работать с заголовками запроса и ответа?
Для запроса: передать объект `headers` в `fetch()` (или использовать `new Headers()`). Полезные заголовки: `Content-Type: application/json` (тело как JSON), `Authorization: Bearer <token>` (авторизация).
Для ответа: `response.headers.get('Content-Type')`. Можно перебрать через `response.headers.forEach()`.

## 5. В чем разница между PUT и PATCH?
`PUT` используется для **полной** замены ресурса (необходимо передать все поля объекта). `PATCH` используется для **частичного** обновления (передаются только изменяемые поля). 

## 6. Как реализовать авторизацию в Fetch API?
Через заголовок `Authorization`. 
- **Basic Auth:** `Authorization: 'Basic ' + btoa('login:password')` (base64).
- **Bearer Token:** `Authorization: 'Bearer ' + myToken` (для JWT/OAuth2).

## 7. Какие способы отмены запросов существуют?
С помощью `AbortController`. Создается контроллер, его свойство `signal` передается в `fetch` (`{ signal: controller.signal }`), а затем вызывается `controller.abort()`. Запрос прерывается, а промис отклоняется с ошибкой `AbortError`.

## 8. Как работать с разными форматами данных?
- **JSON:** `response.json()` (возвращает объект).
- **Текст:** `response.text()` (возвращает строку).
- **Бинарные данные:** `response.blob()` (файлы, картинки) или `response.arrayBuffer()`.
- **Отправка:** Для `FormData` (файлы, формы) `fetch` сам установит `Content-Type: multipart/form-data`.

## 9. Как оптимизировать производительность при множественных запросах?
- **Параллельное выполнение:** `Promise.all([fetch1, fetch2])` (ждет все).
- **Кэширование:** сохранять ответы в `Map` и отдавать без повторного запроса (с настройкой TTL).
- **Отмена:** использовать `AbortController` для отмены устаревших запросов (например, при поиске).

## 10. Какие лучшие практики работы с Fetch API в production?
1. Всегда проверять `response.ok`.
2. Всегда оборачивать в `try/catch`.
3. Использовать таймауты (через `AbortController`).
4. Выносить базовый URL и заголовки в конфигурацию.
5. Использовать библиотеки-обертки (например, `axios`), если нужна сложная логика (интерцепторы, ретраи).
