# Ответы на вопросы — ПР17 (Работа с формами)

## 1. В чем разница между управляемыми и неуправляемыми компонентами?
В управляемых компонентах значение поля (`value`) привязано к состоянию React (`state`), и любые изменения происходят только через обработчик `onChange`. В неуправляемых компонентах данные хранятся непосредственно в DOM, а доступ к ним получают через `useRef` или `document.getElementById`.

## 2. Когда следует использовать управляемые, а когда неуправляемые?
**Управляемые** лучше использовать, когда нужна мгновенная валидация, зависимые поля (например, подтверждение пароля) или динамическое изменение интерфейса при вводе. 
**Неуправляемые** — для простых форм (например, поисковая строка или простая форма обратной связи), когда не нужна сложная логика, а также при работе с файлами (`<input type="file">` работает только в неуправляемом режиме).

## 3. Какие методы используются для обработки событий в формах?
Основное событие — `onChange` (срабатывает при каждом изменении ввода). Для отправки формы используется `onSubmit`. Для потери фокуса — `onBlur`, для получения фокуса — `onFocus`.

## 4. Как обрабатывать несколько полей ввода с одним обработчиком?
Используется атрибут `name` у каждого поля. В обработчике `onChange` извлекается `e.target.name` и `e.target.value`, после чего состояние обновляется динамически:
`setFormData(prev => ({ ...prev, [e.target.name]: e.target.value }))`.
Для чекбоксов используется `e.target.checked`.

## 5. Какие подходы к валидации форм в React вы знаете?
1. **Ручная валидация** в функции `validate()` перед отправкой (как в Задании 2).
2. **Валидация на лету** (при каждом вводе символа).
3. **HTML5-валидация** (атрибуты `required`, `type="email"`, `minLength`).
4. **Сторонние библиотеки** (Formik, React Hook Form, Yup).

## 6. Как предотвратить стандартное поведение формы?
Вызвать метод `event.preventDefault()` в начале обработчика `onSubmit`. Это предотвращает перезагрузку страницы браузером и позволяет обработать данные через JavaScript (отправить на сервер через Fetch/Axios).

## 7. Что такое "поднятие состояния" (lifting state up)?
Это паттерн, при котором состояние (state) переносится из дочернего компонента в ближайший родительский. Родитель управляет данными и передает их дочерним компонентам через `props` вместе с функциями-коллбэками для изменения этого состояния.
