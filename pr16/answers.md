# Ответы на вопросы — ПР16 (React хуки)

## 1. В чем разница между useState и useReducer?
`useState` используется для простых состояний (число, строка, булево значение). `useReducer` используется для сложной логики, когда следующее состояние зависит от предыдущего, или когда состояние состоит из множества полей (как корзина покупок). `useReducer` делает код чище, вынося логику обновления в отдельную функцию-reducer.

## 2. Как работает массив зависимостей в useEffect?
Второй аргумент `useEffect` — массив зависимостей. 
- Если массив не указан: эффект срабатывает после каждого рендера.
- Если массив пустой `[]`: эффект срабатывает только один раз (после монтирования).
- Если указаны переменные `[count]`: эффект срабатывает при монтировании и при каждом изменении `count`.

## 3. Что такое "stale closure" и как использовать функциональные обновления?
"Устаревшее замыкание" происходит, когда эффект или коллбэк захватывает старое значение состояния. Чтобы избежать этого, в сеттерах (например, `setCount`) нужно использовать функцию обновления: `setCount(prev => prev + 1)`, а не `setCount(count + 1)`.

## 4. Когда действительно нужны useCallback и useMemo?
`useMemo` нужен для кэширования результата тяжелых вычислений, чтобы не пересчитывать их при каждом рендере. `useCallback` нужен для предотвращения пересоздания функций, которые передаются в дочерние компоненты (чтобы они не рендерились лишний раз). Использовать их стоит только после профилирования, иначе это преждевременная оптимизация.

## 5. Как useRef отличается от useState?
`useState` вызывает перерендер компонента при изменении значения. `useRef` возвращает объект с полем `.current`, изменение которого **не вызывает** перерендер. `useRef` незаменим для прямого доступа к DOM-элементам (например, фокус на input) или для сохранения предыдущих значений.

## 6. Какие правила хуков существуют?
1. Вызывать хуки только на верхнем уровне (не внутри условий, циклов или вложенных функций).
2. Вызывать хуки только из React-компонентов или из других кастомных хуков. 
Нарушение этих правил ломает порядок вызова хуков и приводит к ошибкам.

## 7. Как создать кастомный хук и какие лучшие практики?
Кастомный хук — это функция, имя которой начинается с `use`, и которая вызывает другие хуки. Например, `useFetch`, `useLocalStorage`. Лучшие практики: давать понятные имена, возвращать массив (как `useState`) или объект (для ясности), инкапсулировать только ту логику, которая переиспользуется.

## 8. В чем преимущества useContext перед передачей props?
`useContext` позволяет избежать "prop drilling" (когда пропсы передаются через 5-6 уровней компонентов, которым они не нужны). Контекст передает данные сразу на нужный уровень, делая код чище.

## 9. Как обрабатывать асинхронные операции в кастомных хуках?
Внутри `useEffect` создается асинхронная функция, и в ней используются `try/catch/finally` для обработки ошибок и состояний загрузки. Также важно возвращать функцию очистки (cleanup), чтобы отменить запрос (через `AbortController`) или предотвратить установку состояния, если компонент размонтирован.

## 10. Какие способы отладки хуков вы знаете?
1. `console.log` внутри компонентов и эффектов.
2. React DevTools (вкладка Components показывает текущее состояние useState/useReducer).
3. Правило линтера `eslint-plugin-react-hooks` для проверки порядка вызова.
4. Плагин React DevTools Profiler для поиска лишних рендеров.
