# Ответы на вопросы — ПР3 (CSS: селекторы, каскад, наследование)

## 1. Разница между селектором по классу и по ID

| | Класс | ID |
|---|---|---|
| Специфичность | 0,1,0 | 1,0,0 |
| Повторное использование | Да | Нет (уникален) |
| Синтаксис | `.name` | `#name` |

ID более специфичен, но должен быть уникальным на странице. Класс можно применять многократно. На практике предпочитают классы — они гибче.

## 2. Как работает каскад

Порядок применения при конфликте:
1. `!important`
2. Происхождение (автор → пользователь → браузер)
3. Специфичность селектора
4. Порядок в файле (позже — побеждает)

При равной специфичности выигрывает правило, написанное ниже.

## 3. Расчёт специфичности

- `ul li.important` → **0,1,2** (2 тега + 1 класс)
- `#site-title` → **1,0,0** (1 ID)
- `.content > .featured-post` → **0,2,0** (2 класса)

## 4. Наследуемые и ненаследуемые свойства

**Наследуются:** `color`, `font-family`, `font-size`, `line-height`, `text-align`.

**Не наследуются:** `margin`, `padding`, `border`, `background`, `width`, `height`.

## 5. Разница между `>` и пробелом

- `A > B` — только прямые дети B внутри A.
- `A B` — все потомки B на любом уровне вложенности.

`>` точнее, но менее гибок. Пробел применяется чаще.

## 6. Зачем `:hover` и `:nth-child()`

`:hover` — стили при наведении курсора (меню, кнопки, ссылки). `:nth-child()` — выбор по порядку (чередование строк таблицы, чётные/нечётные элементы списка). Практика: подсветка строк, интерактивные меню.

## 7. Что делает `!important` и почему осторожно

Переопределяет все остальные правила, включая более специфичные. Использовать с осторожностью, потому что:
- ломает естественный каскад;
- трудно отлаживать и поддерживать;
- приходится использовать ещё более сильные `!important`.

## 8. Псевдоэлементы `::before` и `::after`

Вставляют контент до/после элемента без изменения HTML. Содержат текст, иконки, изображения через `content`. Не входят в DOM, но отображаются визуально. Пример: `→` перед карточкой, `♪` после заголовка.

## 9. При одинаковой специфичности

Побеждает правило, написанное **позже** в файле (или в подключённом файле, который идёт позже). Это называется «порядок следования».

## 10. Как DevTools помогают отлаживать CSS

Показывают:
- какие стили применены к элементу;
- какие правила переопределены (зачёркнуты);
- откуда взято каждое правило (файл и строка);
- позволяют менять значения в реальном времени и видеть результат.

Это ускоряет отладку и помогает понять каскад и специфичность.
