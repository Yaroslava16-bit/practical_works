# Ответы на вопросы — ПР7 (Вёрстка и валидация форм)

## 1. Какие HTML5-атрибуты используются для клиентской валидации?

`required` — поле обязательно, `minlength` / `maxlength` — длина, `min` / `max` — границы для чисел и дат, `type="email"` / `type="tel"` / `type="url"` — проверка формата, `pattern` — регулярное выражение. Браузер сам показывает подсказки и блокирует отправку.

## 2. Разница между `novalidate` и отключением валидации через JavaScript?

`novalidate` — HTML-атрибут формы, который **отключает встроенную** браузерную валидацию, чтобы писать свою. Отключение через JS — например, `form.noValidate = true` — делает то же самое, но из скрипта. По сути, это одно и то же, но `novalidate` удобнее — видно сразу в разметке.

## 3. Как связать `<label>` с полем и почему это важно?

Через атрибуты `for` (у label) и `id` (у поля): `<label for="email">Email</label><input id="email">`. Это важно для доступности — скринридеры читают label вместе с полем, а клик по тексту фокусирует input.

## 4. Какие типы `input` подходят для разных данных?

`email` — для почты, `tel` — для телефона, `password` — для пароля, `date` — для даты, `number` — для чисел, `url` — для ссылок, `checkbox` — для согласий, `radio` — для выбора одного из вариантов. Браузер подставляет нужную клавиатуру на мобильных и валидирует формат.

## 5. Как работает валидация через `pattern`?

`pattern` принимает регулярное выражение. Если введённое значение ему не соответствует, поле становится невалидным. Используется для сложных форматов: телефон, пароль, индекс — там, где стандартных типов недостаточно.

## 6. Какие события JavaScript используются для валидации в реальном времени?

`blur` — проверка при потере фокуса, `input` — сброс ошибки при вводе, `submit` — финальная валидация перед отправкой. Такое сочетание даёт удобный UX: ошибки не мешают во время ввода, но появляются, как только пользователь закончил с полем.

## 7. Как обеспечить доступность сообщений об ошибках для скринридеров?

Через `aria-describedby` или `aria-live="polite"` — сообщение об ошибке привязывается к полю и озвучивается автоматически. Также важно использовать семантические `<label>` и связи `for` / `id`.

## 8. Преимущества `fieldset` и `legend` для группировки полей

`fieldset` объединяет связанные поля в группу, `legend` даёт ей название. Это помогает скринридерам читать форму логично («Личная информация → Имя») и визуально делит длинную форму на блоки.

## 9. Как реализовать кастомную валидацию (например, подтверждение пароля)?

Через JavaScript: на событие `input` или `submit` сравниваем значения двух полей и, если они не совпадают, показываем ошибку. Встроенные атрибуты HTML такое не проверяют — нужен свой код.

## 10. Какие методы CSS используются для отображения валидности?

Псевдоклассы `:valid` и `:invalid` — стилизуют поле в зависимости от валидности. Дополнительно — `:focus`, `:placeholder-shown`, `:not()` для более точных условий. Свой класс `.error` вешается через JS для кастомных ошибок.
